# NVIDIA BIOS Reader v0.3.0

Version 0.3.0 expands the read-only memory analysis introduced in v0.2.0. It
focuses on making the physical RAMCFG layer, translation-table reachability,
and memory-clock conventions easier to inspect without overstating what a ROM
alone can prove.

## Highlights

- decodes physical RAMCFG values as five-bit codes and STRAP2/1/0 `L/M/H`
  electrical levels;
- distinguishes all Memory Information records, non-`Skip` rows shown by the
  GUI, and descriptors referenced by the declared translation table;
- uses compact `Unmapped` labels in the grid while retaining complete wording
  and offsets in detailed reports;
- separates the NVIDIA/MODS/Afterburner MCLK domain from the lower
  memory-device clock shown by GPU-Z;
- applies `MCLK / 4` for GDDR6 and `MCLK / 8` for GDDR6X device-clock
  estimates;
- adds focused tooltips for RAMCFG, density, organization, timing coverage,
  logical groups, MCLK, timing IDs, CONFIG fields, and ROM offsets;
- improves live window resizing by batching child-control positioning and
  reducing redundant column and tooltip geometry work.

## Important interpretation limits

- `FULL` means complete timing-record coverage for used ranges. It is not a
  guarantee of runtime stability.
- `Unmapped` means the descriptor exists but no code inside the VBIOS-declared
  translation-table count selects it.
- Density is per memory device and does not establish total board VRAM.
- `x16 / single-sided` and `x8 / double-sided clamshell` describe decoded
  firmware profiles; they do not independently prove physical PCB population.
- Device-clock values are inferred from observed tool conventions. Original
  MCLK selector ranges and ROM offsets remain available for verification.

## Regression scope

The release candidate parsed 116 unique NVIDIA ROM hashes without error. The
set covered TU102, TU104, TU106, TU116, TU117, GA102, GA104, GA106, AD102, and
AD104. Parsing success should not be interpreted as validation of every
generation-specific field.

The tool remains read-only and never modifies or flashes the input VBIOS.
